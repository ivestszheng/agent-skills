# 分析口径与指标定义

统计分析前先统一口径，否则「花了多少」在不同工具里会差出一倍。

## 1. 净支出（最常被问的「我这个月花了多少」）

```
毛支出 = SUM(money) WHERE type = 0 AND NOT 平账
退款   = SUM(money) WHERE type = 20
净支出 = 毛支出 - 退款
```

- 不算 `type=2` 转账（左右手互倒，不是消费）
- 不算 `type=3` 信用卡还款（还款是资金搬运，消费已在刷卡那笔记过）
- 不算 `type=5/6/9` 借出借入（是债权，不是支出）
- **必须剔除平账**，否则资产浮亏会被算成消费

## 2. 收入

```
收入 = SUM(money) WHERE type = 1 AND NOT 平账
```

分类名以用户库里的 `category` 表为准（钱迹内置分类大致是工资、奖金、红包、外快、
其它收益、公积金、医保、退税、二手置换这类）。
其中「公积金」「医保」是**账户划入**（钱进了公积金/医保账户，不能当现金流花），
分析可支配收入时应单列或剔除；「其它收益」里常混有平账分录，必须先减掉。

## 3. 结余与储蓄率

```
结余    = 收入 - 净支出
储蓄率  = 结余 / 收入
```

参考区间：储蓄率 ≥ 40% 优秀，25%~40% 健康，10%~25% 一般，< 10% 需干预。
注意：**收入漏记会直接让储蓄率失真**，先核对收入笔数。

## 4. 资产与净资产

```
资产 = SUM(user_asset.money) WHERE type IN (1,3,4)   -- 资金账户、押金、投资
负债 = SUM(user_asset.money) WHERE type = 2          -- 信用卡等
净资产 = 资产 - 负债
```

`type=5`（借入借出）当前余额为 0 说明已结清，不要计入资产。

按可动用性分组（建议的报告分组）：

| 分组 | stype |
|---|---|
| 股票/权益 | 41 |
| 债券/理财 | 47, 48 |
| 储蓄型保险 | 47 中的两全险/年金险，或按资产名判断 |
| 现金活期 | 12, 102, 107, 11 等 |
| 公积金/医保 | 17, 18 |
| 押金 | 35 |

浮动盈亏：`money - extra.initmoney`（`initmoney` 是记录成本）。

## 5. 应急金覆盖率

```
覆盖月数 = 可动用现金 / 月均净支出
```

建议 3~6 个月。只看「现金活期」分组，**不要把储蓄型保险、公积金算进去**
（前者锁定期长，后者取不出来）。

## 6. 预算执行

```
执行率 = 该分类实际净支出 / 年度分类预算
```

- 年度预算取 `user_budget.type=2 AND flag=2`
- 月度预算取 `type=1`
- 按时间进度折算：进度 = 已过月数 / 12，超进度 10 个百分点以上要留意
- 年度预算里的「保险」「电器数码」这类是一次性大额，线性推算会失真，需结合往年判断

## 7. 集中度

```
单一持仓占总资产比 = 该资产 money / 净资产
```

个股占总资产 > 25% 一般就算集中度过高。

## 8. 消费活跃度

- 笔数：月均笔数反映记账习惯，先算 `COUNT(*) / 月份数` 再作为基线看波动
- 单笔均额：净支出 / 笔数
- 高频小额分布：按分类看「笔数多但金额小」（餐饮）vs「笔数少但金额大」（住房、保险）

## 报告建议结构

1. 概览 KPI：净资产、期间收入、期间净支出、结余与储蓄率
2. 资产配置（环形图 + 明细 + 浮动盈亏）
3. 月度收支（双柱 + 表格）
4. 支出结构（分类横向条形）
5. 收入结构（表格 + 占比）
6. 预算执行（执行率 + 进度条）
7. 结论与建议：先「健康项」，再「风险点」，最后「可执行动作」

风险点写法：每条给**量化的证据**（例：「现金活期 X 元 ≈ 0.8 个月支出，低于 3 个月下限」），
数字一律取当次分析的真实结果，不要只写「建议多存钱」这类空话。

## 9. 输出脱敏

给用户的报告、Markdown、JSON 里**不应出现**：完整卡号、持卡人姓名、身份证号、
手机号、账号标识（`userid` / `memberid`）、账本成员昵称、含登录用户名的本地路径。
统一走 `qianji.mask_text()` 与 `qianji.mask_path()`，详见 SKILL.md 的「隐私与脱敏」。
